# Required retained projectile payload provenance

The exact native snow-mage SimpleProjectile has `_stopWhenSourceInvalid=0`. ColdAttack carries a loadFromDB e2c_cold active buff with source freeze10. The controlled public failure starts a real skill at0, launches at20, kills the source at22 and impacts at23. Arts damage300 survives, source SP remains0, but target Cold23 is missing because the frozen4ef generic buff.application effect requires an active source. This is a required consumer gap, not an approved reference policy or a completed snmage model.

Preserve4ef, the module bytes and its original failure. Implement any fix only in a new generic candidate. No Cold ID branch, source activation, arbitrary dead-source cast, broad effect bypass or caller-provided `projectile_impact=True` authorization is sufficient.

1. Mint an impact capability only inside the actual ProjectileSystem._hit reservation for an active retained projectile. The source-invalid lifecycle policy must explicitly be `retain`, source and target must match the manager's current projectile instance, and the current target must be a legal reserved hit. Max-hit/duplicate quota remains enforced by the existing reservation. The capability must expire when that synchronous hit dispatch ends; nested callbacks must use the same actual hit context, and later public commands cannot reuse it.
2. Bind provenance to the actual projectile instance ID, its generation/launch identity, original source ID, source incarnation at launch, immutable launch source snapshot, trace/reserved target ID and target incarnation, current hit reservation and pending impact dispatch. Resolve the actual manager state at use time, never trust a free-form effect field, Boolean or stale cast/actor list index. Removal, invalidation, generation change or departure of the pending impact denies use. Atomic rollback must restore state and reservations without reviving an old capability.
3. Pass the context through the generic effect dispatcher and nested on_success effects. Buff application may consume an explicitly validated retained-impact capability to authorize the *origin* source while the target still passes normal active/immunity checks. The original source remains inactive/dead. An unrelated target, foreign source, manually submitted skill, scheduled effect without that impact, spoofed snapshot/instance, refreshed generation or ended impact is rejected.
4. Pure application rules receive the bound immutable origin source view rather than the actor's next incarnation. Owner/target status, current Buff handles and target attributes are sampled freshly at use time. Persist an explicit origin identity/provenance in the applied Buff if necessary; timers and source-independent Cold/Frozen clearing must not later interpret a reborn actor with the same ID as the original source. Existing source death checks, no-op/RNG behavior and atomic finite-plan validation continue to apply outside this narrow capability.
5. Recheck provenance and target incarnation after synchronous callbacks. It must not continue an old application plan after retirement/rebirth, touch callback-refreshed Buff handles or modify the source actor. Cold/Frozen policy and existing source5/10 values stay in content.

Required candidate tests: the preserved native failure must now deliver real Cold10 at23 with expiry323, while damage300 and source SP0 remain unchanged; normal attack and ordinary live-source Cold witnesses stay byte-consistent for observations under the new runtime identity. Public dead-source casts/effects, forged context, foreign source/target/launch refs, completed/invalid projectile, duplicate/nested impact and generation mismatch must fail without state/RNG writes. Source rebirth and target retirement/rebirth during a callback must preserve origin identity and freshness. Durable disk CP taken in flight before source death and from-head public replay must match complete event and continuation hashes.

Root owns candidate implementation and independent review. This file is an implementation contract proposal, not proof of the missing capability.
