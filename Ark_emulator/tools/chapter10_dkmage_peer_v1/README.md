`verify.py` consumes the frozen source module `build()` and `providers()` interface
on joint core9a. All receivers, public controls, map, death scene, same-wave keeper,
numerical assertions and RNG oracle are independently constructed. Author fixtures
and assertions are not invoked. Source freeze inventory, the saved module, closure,
helpers and dependencies are hashed before/after the run; freshly built module
must equal the saved frozen module exactly.

spacing. Baseline source attack550 applies four sequential .85-scaled health/EP
impacts with DARK.3 and no fifth hit. Its original shared cast begins0, launches37,
finishes66 and launches the next cycle157. A separate public current-attribute gate
buffs source attack at41 and receiver1 resistance at43; their effects are observed
at actual impacts. Complete source ownership keeps exactly one chain ability and
no invented SP resource or extra EmptyAbility cast.

All native AdvancedSelector fields are compared to the original component,
including postFilter4, abnormalFlag25/combo2 and excludeAbnormalFlag46. Actual gates
exercise air acceptance, category4 rejection and target-free/camouflage/invisible
rejection. Preserving the full source record does not prove native post-filter or
priority method equivalence; selection order remains an explicit reference policy.

The native DB skills/spData are null, _combat and _attack alias the same RangedAttack
path, and EmptyAbility's raw fields contain no selector/clock/SP. The explicit
lifecycle-owned data packet is actually consumed by the EP provider. Absent owner,
wrong class and wrong path each fail at the actual impact, with health/EP unchanged.
The class name itself is not used to infer an empty executable skill.

The independent managed death scene kills the source through a public true-damage
skill at11. Native BB child dzomg2 is born at41, inherits the original route and

samples and the .10000000149011612 point-range result. The keeper prevents a false
terminal wave completion around the pending birth.

Nine new disk checkpoints are written, reopened from actual bytes and restored.
Forward/restored/public-input-head runs compare complete snapshot, ordered events,
event count, continuation state and the complete checkpoint object. The final c run
is the evidence selected by `freeze.py`; earlier local fixture diagnostics remain
separate. Runs use fresh E:/ArkSimLogs paths and worker leases. Raw files are cleaned
after small results are saved; recorded checkpoint references are not reusable
recovery material. A separately successful death probe initially hit launcher
protection during cleanup; the policy retry after launcher exit cleaned all its
raw files and saved `cleanup.retry.json` alongside its original completion receipt.
