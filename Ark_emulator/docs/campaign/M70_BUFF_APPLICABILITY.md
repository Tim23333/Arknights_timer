# M70 Buff applicability and control immunity

The frozen candidate is `unpack_work/campaign_m70_buff_applicability_v2_candidate`, implementation `0b5a6a6b09cfbb631bd69dd67079814e90bccbe4d5d5737c1d33f869b7fab647`. Primary, M68, the old unwired M70 WIP, M61/M74 and all live scenarios were kept unchanged. This is a declared mathematical model and API/source-operand verification; `client_verified` and formal approval remain false.

A Buff may explicitly bind `active_rule` or `control_rule` to the new pure Boolean `buff.applicability` contract. Inputs include the actual owner/source snapshots, persisted instance, effective selection-state projection, and Buff parameters. Strict Boolean outputs and exact contract references are checked. The catalog has 93 contracts, one more than this frozen M68 parent. No binding means the original path, with no contribution-state fields or applicability calculation events.

`active_rule` controls attributes, damage hooks, selection flags/immunities, aura/toggle contributions, event reactions and periodic/immediate effects. A false decision preserves the underlying instance and its duration/periodic clock. Its removal callback still executes. `control_rule` gates movement/attack/ability/block restrictions and explicitly requested interruption; it preserves noncontrol properties. When previously suppressed control becomes applicable, an existing cast is interrupted only if the Buff requests `interrupt`. Control and active effects are rechecked between synchronous effects so an effect that disables its own Buff cannot execute later contributions.

Contribution decisions are stored in World and stabilized within the caller transaction. Effective flags and immunities are formed from intrinsic state and current active contributions, with enum indices and combo indices kept separate. Inactive Buffs do not supply their previous immunities or selection outputs. Mutually dependent contributions that oscillate exhaust a bounded stabilization budget and fail atomically. Getters and pure selection projections read the stabilized state without evaluating rules, sampling RNG or changing World/events. Reentrancy guards always clear in `finally`.

Movement damage settles the old active tail before deactivation. Travel while inactive is discarded before reactivation, so it cannot reappear as a later damage packet. After a tail callback the stabilizer reloads actual World state rather than reinstalling stale instances. These tests use the existing Weedy distance formula and actual movement API, separately labeled from public command replay cases.

The new source-backed package is `packages/campaign/chapter04_boss/m70/immunity.reference_model.json`, SHA `8e0731886294b1ff0d781d397d935b2bf6229740b673e55466ae46e53e11fc34`. The builder locks the frozen raw source plan, actual enum dump, previous exact FrostNova stats, and Chen source package. FrostNova's typed DB booleans consume STUNNED 0, SILENCED 12, FROZEN 16 and LEVITATE 25 as intrinsic immunity indices. The actual `frstar_c` passive supplies SLEEPING combo immunity 0; Chen's selected source Buff supplies flag 0 and duration 1.5 seconds. These are operational state operands, not numeric attributes or merely metadata.

The source fixture retains HP25000 and implements an explicit external phase-removal driver: initial sleep immunity suppresses an already-applied sleep Buff, then removing that immunity causes the existing sleep control to take effect immediately. The driver is synthetic and is not presented as native FrostNova casting or real rebirth. True delayed rebirth from M61/M74, whole Boss skills, status resistance duration/dispatch details and black ice remain separately scoped for subsequent integration and user feedback.

Fresh verification produced 24 new cases (4.01 seconds) and 88 unchanged compatibility cases (6.10 seconds). Two public-command cases include ordered disk checkpoints and command replay, including the source-backed phase fixture. Other cases cover mixed silent Buff properties/selection flags/immunities, independent combos, intrinsic state changes, expiry, cast interruption, periodic/event/hook suppression, compulsory removal callbacks, movement tails, strict wrong-contract/non-Boolean rejection and real rule-failure/oscillation rollback. The initial isolated-context failures were corrected with optional feature detection, and their log is retained. A proposed synchronous reaction-to-emit test was revised because the existing domain reaction contract queues notifications; it was not counted as a core defect.

No state, numeric operand, event or RNG entry is removed from comparison. This bounded witness is not a full-stage claim.
