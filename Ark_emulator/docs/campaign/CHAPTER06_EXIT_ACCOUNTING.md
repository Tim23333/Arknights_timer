# 第六章特殊退出清算

固定源 `source.plan.json` 内部main_06-15（显示6-17）的唯一出生动作带严格布尔值 `isUnharmfulAndAlwaysCountAsKilled=true`。本地原生声明还保留两个独立Enemy.Options字段 `unharmful`／`alwaysCountAsKilled`，以及接受这两个选项的出生接口。字段声明证明输入关系，不证明实现正文。

当前选用可替换的退出参考规则：无基地生命损失，真实路线退出时获得关卡击杀信用。规则不抑制敌方攻击，不改变HP，不把退出伪造为真实死亡，也不发出combat.kill。死亡仍由真实伤害与生命周期单独处理。完整关卡的时间线仍等待实际演员终结；不会在出生时清除或提前算死Boss。

源绑定模块见 `packages/campaign/chapter06_exit_accounting/reference_policy.json`，保存原出生动作和固定计划SHA。它是待整关转换消费的显式profile，不是已完成的6-17敌人／NPC／剧情模型。

## 通用接口

内容在实体生命周期中可声明 `exit_rule` 和 `exit_parameters`。`lifecycle.exit` 是纯计算，接收实际实体、退出原因和内容参数，返回精确记录：

```json
{"base_life_loss": 0, "kills_delta": 1, "leaks_delta": 0}
```

基地损失必须有限且非负，两个计数必须是严格整数0或1，单个演员最多获得一次击杀／漏怪信用。未声明规则的实体继续使用既有退出逻辑。内容可以替换表达式、计算图或提供器；不会在内核分支中识别方舟敌人ID或原生特殊标志。

执行器先计算并验证完整计划，然后原子提交，保存实际退出声明防止重复清算；真实演员状态为exited。退出信用事件记录规则、损失和计数，死亡事件和击杀归因保留独立身份。
