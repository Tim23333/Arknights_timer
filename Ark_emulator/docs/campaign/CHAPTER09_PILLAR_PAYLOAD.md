# 石柱载荷与石像鬼来源联结

递归来源提取补齐了石柱和选技引用的八个Buff模板，缺失数为0。
`source.closure.v1.json` 保存原始BSON、字节摘要和离线读取身份。
`trap_dupilr_trait[startdead]` 的结束动作会取得candead资格并清除未保留Buff；
这部分是持续两秒的受损状态，不是把石柱血量恢复为1或直接删除石柱。

当前可执行的`collapse.payload.v1.json`实现倒塌载荷：

- 四个方向分别使用源范围2-2的原地与前方两格。
- 接受的敌方角色在1.5秒后受到ATK12000的真实伤害及10秒眩晕，地面和飞行分别测试。
- 我方角色即使target-free也按该分支撤退；装置使用独立类别分支，不和敌人伤害混算。
- 两个可放置方向格生成HP100、阻挡数3的真实碎石实体，所有者退出后保留。
- 碎石层改写可部署及高度等源字段，保持原地块通行属性；没有从redeploy5或视觉Buff0.5推断固定寿命。
- 碎石死亡后清理自己的地形层，并释放实际阻挡。

10项作者检查在v7实际通过，又在合入岩石接口后的v9重新通过，包含四方向、目标资格、
晚进入范围者、三实际路线敌人阻挡与第四者未阻挡、地形清理和磁盘检查点／公开回放。
两次开发夹具的误假设保留为原失败结果：Buff不存在`applied_at`字段、默认地块mask为1。
最终检查改用实际Buff事件时间和原地块passability，模型数值没有调整。

石柱本体实际持有`buff/ch9/pillar/trait`，该身份提供给石像鬼构造器，
不再使用测试专用的假柱标记作为正式外部依赖。
v9的真实柱体公有技能在第47刻命中石像鬼，使其进入mode3并直接死亡，未开始复生；
同一次运行的真实CP续跑和从头公有回放完整相等。

此时石柱仍不是完整消费者：受击来源／命中范围取消、精确HP0保持的两秒受损状态、
下一次攻击的方向选择、邻近我方自动倒塌，以及爆破装置仍需接入。
这些依赖继续开发，不以已通过载荷场景签整柱或第九章完整关卡。
来源与模型数值验证均不提升客户端验证状态。

新候选和运行结果保持各自身份；所有大检查点与日志在E盘验证后已按用户要求清理，
源码、来源和精简结果保留在仓库。

后续原生地图准入发现`tile_bigforce`之外，一格普通`tile_floor`和一格`tile_wall`也带
`base_force_level=1`黑板。同tileKey其他格并没有该操作数，旧按tileKey统一profile不能完整消费。
新的隔离cell-field候选保留原地图字节对应字段，使用`map.tile_cell_mechanics`按canonical `row:col`
声明已实现的占用Buff场，拒绝越界、非标准键、未知机制和未完整绑定的黑板。
四个源格子的玩家角色获得基础力度+1，离开时移除所属贡献；声明与实际CP/head均验证。

原生9-18三份石柱记录共享同一个alias。新转换层保留三份raw record和原alias，
将运行注册键绑定为`main_09-16/tokenInsts/0..2`；直接使用模糊alias会拒绝，按record key可精确解析。
完整源地图、四场owner和三个不同石柱actor的实际磁盘续跑及公开回放通过。
这些是输入与地图模块的准入进展，不是34出生整关已执行。

9-19另有一个`tile_road`格携带感染黑板180／300秒／ATK0.5／ASPD50。
该格通过同一cell profile引用第八章已来源绑定的感染消费者，原`tile_road`身份不变。
实际30、60刻分别执行无来源180真伤，磁盘CP／公开head完整一致；没有因tileKey不是
`tile_infection`就忽略该格黑板。两关地图所有非空操作数都有明确消费者，
地图框架仍拒绝未知cell机制、越界身份与未绑定字段。
