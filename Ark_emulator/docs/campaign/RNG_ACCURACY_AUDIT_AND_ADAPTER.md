# RNG source accuracy audit and snapshot adapter proposal

Current V2 random replay is deterministic mathematics; it is not evidence that intermediate random decisions match the game. The latest user goal keeps unit HP real, sets base life99999, permits leaks and requires accurate full simulation. No life/stat/content override is made here. No phone, ADB target, memsrv or live reader was opened. The original audit is `validation/campaign/rng_accuracy/source_audit.json`, SHA256 f8d0299c9727f4a894bea18e63b44e933e26258a8c49aa13fc2be965e97b5256, locking all actually read source bytes. It contains 4 actual V2 sample call sites and 34 content stream references.

## What is established, and what is not

V2 kernel defaults to python-mt19937/sha256-stream-seed-v1. It hashes JSON[root_seed, logical_stream] into a separate integer for each named stream and gives that value to Python Random. sample returns Python's float and logs per-stream index/time. Snapshots preserve algorithm/version/factory fingerprint, generator states, counts and samples. Restore validates those identities and logs. This is a sound model-replay interface but changes algorithm, initialization and stream partition relative to the hypothesized game.

Local `Ark_data/dump.cs`, SHA d25fb9fb7ec81253f112d9090e4550cd37a273ace56085d37610bb67c1e3a88f, actually declares BattleController IBattleRandom s_randomImp/s_randomTrivial, BattleRandomWrapper.m_random, IBattleRandom Value/Next/NextDouble/Range/RandomVector/Shuffle/Dice and LegacyRandom's two cursors plus SeedArray. All inspected method bodies are empty declarations. RandomFactory.DEFAULT enum and Create(seed) declaration cannot prove DEFAULT implementation or constructor steps. The audit independently locks both local dump paths and preserves exact excerpts rather than relying on outdated line numbers/comments.

The project game tool implements a Knuth-style state recurrence, with DotNetRandom(seed) explicitly initialized at cursor21. Historical comments report observed31; no original live raw snapshot/episode fixture was supplied for independent review here. Synthetic 31-state tests verify the recurrence implementation, not a game constructor. The .NET [primary compatibility implementation](https://github.com/dotnet/runtime/blob/main/src/libraries/System.Private.CoreLib/src/System/Random.CompatImpl.cs) independently shows the21 initialization and subtractive update; it does not prove Torappu LegacyRandom uses that constructor. This primary page is an algorithm comparison, not the game's method body.

The tool's UI snapshot omits the complete seed array and emits rounded prediction/history fractions. It cannot initialize an exact backend. A verified physical engine/role label identifies the static slot object in a capture; it does not associate every talent, spawn coordinate, shuffle or selector call with that slot. No assumption that every meaningful effect is imp, every cosmetic effect trivial, or spawn is its own physical stream is accepted as a proven call mapping.

## Actual evidence-gate defect and bounded repair

Original recover_advanced compared only seeds and inext. tracker._observed_key dropped inextp. The saved synthetic counterexample starts at(0,21); one true step predicts(1,22). Same seeds/inext but legally readable inextp32 was incorrectly accepted as that one draw, despite full endpoint inequality. A FakeReader poll also adopted the mismatch as status ok. This is a comparator defect, not proof of a particular device failure.

Old six helper files are archived byte-for-byte under `validation/campaign/rng_accuracy/original_helper`, with SHA records; the old failure report is unchanged. Authorized repair makes DotNetRandom.matches require seeds,inext,inextp and tracker provide that triple. Incomplete Knuth observation raises explicitly. Legalp32 is still readable; it is rejected when it differs from the predicted endpoint. No seed constructor, recurrence, stream mapping, MT path or V2 core was changed. Engine/header, README and memscan wording now distinguish declarations, historical observations and unknown bodies; no old log was rewritten.

11 independent tests passed, plus69 existing FakeMem checks. Tests cover valid21/31 recovery across wrap and37/70/120 steps, mismatch rejection with prior state retained and status lost, partial endpoint error, and700 MT steps across twist. Fix report SHA bdbd4b86d190efda526802f7fac9ec8b2d1eef7107d97edcfd509c7a5719802e; patch SHA a767f4ffe2fe357358032c66e7c0087f9cdc81abcccd0056885079d13b2cbed0. ## Minimal proposed generic adapter

Do not replace the current default merely with a factory calling DotNetRandom(derived_seed). AlgorithmSpec currently hardcodes SHA seed derivation, uses one algorithm selection and independent logical generators, and recreates each generator through factory(seed) during restore. A factory ignoring that seed must not retain an identity claiming native seed initialization. Returning one shared backend object for two aliases is also unsafe: per-alias snapshots/restore and copied factory closures can duplicate or mutate shared physical state.

A future independently versioned candidate should add an explicit initialization mode, `derived_seed` or `observed_state_bundle`. The bundle contains backend algorithm/version/source fingerprint, game build/platform/asset identity, capture/episode origin, complete per-physical-engine state and a proven logical-to-physical routing manifest. Knuth state is all56 integer values plus both cursor indices; preserve observed separation rather than resetting to21/31. MT needs all624 unsigned words and index. Validate types/ranges/array lengths and reject incomplete summaries or unrelated engine builds. Constructor mode cannot be enabled as native until its seed body or a constructor comparator is proven.

Backend operations should separate raw advancement from transformations: next_raw returns raw output and new full state; next_double/value/range/dice/uniform/shuffle are explicit versioned adapters with declared raw draw budget and numeric precision. Keep legacy sample() as a model-compatible double operation, but do not equate it to all native interfaces. Native float rounding may differ from double; integer large-range/PRD/shuffle/rejection can consume multiple draws. Unknown operations must remain pending rather than receiving a generic one-float formula.

Store physical engines once. Logical aliases route to that record, sharing one consumption sequence if and only if identity/mapping is proven. Logs should include logical consumer ID, physical engine ID/role, operation, raw outputs, pre/post full-state hashes, logical tick, consumer ordinal and source/content provenance. Preserve exact values or IEEE bits, not six-decimal UI fractions. At captured origin local count0 means relative observation start; do not fabricate absolute lifetime consumption index. Unmapped streams must reject verified-game mode, while explicitly named model mode remains available.

Initialization bundle SHA, alias manifest SHA, operation profile SHA and backend/source fingerprints must enter program/runtime/replay identities. Transaction rollback must restore physical engines, all aliases/counts/logs together; restore stages private backend copies, never mutates factory closure state or an active source session. Unknown algorithms/wrong build/stale snapshot/unmapped stream reject before state changes. Existing no-config model path need not add a default binding or event.

## Trace comparison plan and acceptance boundaries

1. When an authorized appropriate emulator is available later, export raw complete imp and trivial states and object/class/build identities at a reproducible boundary, with repeat cursor guards around array reads. This audit does not perform that capture. Validate all arrays and both cursors; discontinuity/version/object replacement starts a new episode rather than silently reseeding.
2. Use tiny controlled scenes for single spawn, one target choice, one talent probability and one packet hook; isolate deterministic UI/animation conditions and mark any remaining trivial consumers unknown. Advance from the same captured state; compare full next endpoint and raw sequence, not only returned output or cursor1. Preserve mismatches as failed evidence.
3. Recover operation draw budgets and conversion/order separately. A global imp sequence match does not identify which consumer used which draw; assign consumer mappings only with source body or controlled call-site trace. Candidate set enumeration, empty/probability0/1 cases, exact numeric precision and multi-target ordering need explicit negative/boundary cases.
4. Compare game observed outcomes and intermediate HP/SP/DP/damage/position/target identity to simulation under the same content/commands/timing origin. RNG alignment alone cannot validate formulas or movement. Lack of native body/trace remains a blocker to actual accuracy, irrespective of model victory/zero leak/full CP/replay.
5. Finally execute adapter snapshot/restore/atomic failure/commands replay and wrong-version/alias/incomplete-snapshot tests under one frozen identity. Report model checks, native raw-sequence comparison and outcome comparison as separate scopes. No old mathematical receipt should be relabeled client verified.

This document is a design and source audit, not an implemented V2 RNG adapter or gameplay accuracy receipt. M25 and every V2/candidate core remain frozen.
