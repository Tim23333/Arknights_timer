# 中途数据准确性验收

目标是固定12人配置、第0–17章末两关共36关。基地生命值99999是测试设置；干员和敌人的HP、成长、技能、天赋和公式保持来源实际数值。允许漏怪和干员退场，要求出生到终结的全过程完整执行，并逐项证明中途行为准确。

用户最新指定验收顺序：当前先使用此前参考网站、公开固定数据和已提取资产完成仿真与数值／机制核对，之后由用户统一实机验证反馈。本文的客户端采集方案是后续可选对照基础设施，不再作为本次开发交付前置条件。明确规则的完整实现、参考出处和独立测试仍是当前门；源冲突与模型假设单列，客户端未验证状态保持真实。

独立公式审计与全程重放分开验收。新增 `tools/trace_audit/` 工具只读取实际计算trace，以独立算术核对属性层、伤害／最低伤害、治疗、资源上限、费用和恢复，不导入运行时计算器作为预期。核对输入→raw→value及嵌套stage，而不是仅比较终局HP；篡改中途raw但保持最终资源不变的反例必须失败。已知公式一致仍需实际内容参数／来源绑定，未知规则、来源字段或未触发分支保留pending。短场景与单公式通过不能推出36关全部中途数值通过。

第六章最终story源5184／内核d509整流30249事件新增固定配置审计：原始4单位初HP、出生前零容量调整的真实后续身份、87次HP前值＋delta／value、84次damage与实际HP扣减、38次PURE／BUFF血耗的2000原金额／夹取／owner／时点，以及一个cast仅一个source-area／每成员一个packet。六个保最终状态不动而篡改中途delta、damage、血耗金额、出生HP或重复Area的反例均拒绝。它不认证任意成长、复生、custombounds或动态基值改写。

同一流的既有V5已知标准规则审计另外检查15186公式、2235缓存、141嵌套和92个damage graph上下文；8908个实际actor body／源base身份一致。自定义未知规则、时序和几何仍单列pending，不将这些范围的通过合并为全部准确。HP守恒也无法发现一次施法重复两次且每次内部守恒的伤害，所以source-area单包次数必须另外验收。

来源主体绑定另由 `body_binding_v1.py` 只读检查真实entity.created／registered到actor ID与definition映射、trace中source／target／owner body身份和基础属性。源短轨迹2691次body／base检查相同；保持最终damage不变却改source ID、target定义或源ATK的3个反例实际拒绝。尚未宣布出生前的引用、动态base重写、有效属性、成长覆盖或HP容量另需精确契约，不能由body身份一致自动证明。

全5-9日志首次审计发现callback包装与graph节点包装不同：真实callback记录value及child trace，graph节点同时有raw/value。旧工具强制两者同形产生失败，原报告保留；新工具须按已证明schema分别核值，不能以缺字段直接补造数值或放宽全部节点。完整重审前该关中途数值仍待验收。

## 三类证据

| 状态 | 证明内容 | 不自动证明的内容 |
|---|---|---|
| 来源字段核对 | 原始表、关卡、资产、枚举、引用与转换一致 | 空方法声明不能证明算法正文；不同版本来源不能自动组合为同一客户端 |
| V2模型验证 | 明确规则的伤害、状态、命令、检查点、回放及生命周期一致 | 自身确定性不能证明游戏按相同规则运行 |
| 实际游戏对照 | 同版本、同配置、同操作和时间基准下，实际状态／事件与模型逐项匹配 | 未采到或未比较的字段、时段、单位和调用仍为pending |

历史2/36模型收据继续保留其原输入身份。99999输入需要新的运行证据，实际准确性不能由包内metadata或模型报告自行批准。

## 对照输入与时间

每段对照保存游戏平台/build、原始关卡／表／资产SHA、固定12人的养成与选技、种子或完整随机初态、完整公开操作、采集器源码/偏移版本、模拟器源码及内容身份。
教学关卡的原生卡片与固定12测试覆盖需分列；普通原生教学录像不能作为固定12整关的相同配置对照。可以先比较不受编队影响的敌人、路线、时间线和独立受控机制，并明确适用范围。

时间对齐使用原始逻辑帧、采集前后帧校验及已证明的映射。当前模型常用1/30秒刻，项目采集器声明按1/60秒读取；不能直接把两个刻号当作同一时间，也不能用UI四舍五入的秒数建立精确对齐。
采样60Hz也不能推出客户端逻辑60FPS。现有 `enemy_reader._decode_battle_clock_snapshot` 解码实际fixed-frame计数、Q32.32 playTime和delta，需保留这些原值并由采集证据建立时间映射，不把主机轮询频率用作客户端逻辑频率。
暂停、加速、控制锁、教学等待和采集丢帧均单独记录。丢失的样本不能用上一帧补成通过。事件顺序需有实际证据；最终状态相等不能抹掉中间不一致。

## 逐项覆盖

| 对象 | 必需观测 | 当前主要缺口 |
|---|---|---|
| 关卡 | wave/fragment/action出生，管理门，控制开始/确认/取消，预定义激活，结束 | 36关仍逐章转换；99999全程证据单独积累 |
| 单位 | 来源ID到运行实例的映射，活跃/休眠/出生/死亡/漏怪，HP与最终属性 | 不以临时内存地址或仅敌人类型ID跨帧匹配实例；同类型多个单位需独立映射 |
| 资源 | DP/SP/HP变化前后、来源、技能付款与恢复冻结 | 恢复粒度、舍入、同帧先后及未触发分支需边界对照 |
| 伤害/治疗 | 来源/目标/类型/数值/前后HP，减伤、盾、增伤、钩子 | 命中前后属性采样和多包顺序不能仅由字段推断 |
| 技能/Buff | 开启/结束/打断/付款、实例、堆叠、刷新、到期、控制成员 | native callback正文与客户端逐帧对照仍未闭合 |
| 敌人决策 | mode/state、候选与目标、移动/攻击互斥、阻挡、控制 | M24是明确数学profile，原生决策正文仍pending |
| 目标筛选 | 侧别、运动/类别/职业、不可选中/迷彩/禁疗、Buff贡献 | M25枚举/字段已核对；相对侧别与原因汇总仍需实际证据 |
| 空间/弹道 | 连续位置、路线/检查点、隐藏/出现、发射/命中/碰撞/寿命 | 原生路径、弹道算法、失效策略和精度仍需对照 |
| 随机 | 全数组与双游标、物理流、raw消费、具体操作及前后状态 | 已修复工具漏比游标；种子构造/工厂/调用映射仍pending |

数值比较先保留原始值或IEEE位表示。逐字段声明精度和已验证的误差依据，不能设置统一大容差消除差异。离散ID、状态、顺序、枚举、计数与命令结果精确比较。坐标或浮点需要容差时保留原始差值和第一次分歧，并区分公式误差、量化误差和采集误差。

## 已实现离线比较器

`tools/compare_campaign_trace.py` 消费标准化trace和显式比较合同，不连接设备、不猜测时间对齐、不补帧、不四舍五入。合同锁定关卡/build/platform/content/roster/commands/episode，声明逐帧覆盖、逐字段映射和精确有理数时间关系。混帧、缺帧、缺字段、重复帧、不可表示的模型时间与中途数值差异都拒绝或保存失败结果。
离散字段采用严格类型和值比较，bool不等于int；连续坐标容差必须逐字段给出依据。报告保留第一次分歧、原始值/差值、输入和工具SHA、覆盖与未覆盖范围。比较通过也保持actual_game_accuracy_verified=false，等待原始采集／标准化来源和独立审阅。

实际V2短场景以独立synthetic预期比对HP100@0/6、HP80@7/8和敌人静止坐标，CLI匹配exit0；故意把中途HP改为81而终局仍80，CLI准确记录tick7差异并exit1。证据位于 `validation/campaign/trace_comparison/cli_verification.json`。这些是比较基础设施验证，未冒充客户端轨迹。

`tools/export_campaign_model_trace.py` 已提供模型侧标准导出入口：明确runtime/core、内容／命令SHA、seed、时间样本与字段路径；比较content identity必须等于实际program fingerprint，场景显式seed不得被计划覆盖。导出实际HP、连续位置、系统状态或完整RNG状态，不调用calc生成额外事件，缺失字段直接报错。两项只读/缺失路径测试已实际通过。真实M26场景4帧×2字段标准导出后，与相同synthetic预期CLI比较8值通过，来源guard一致。
另已实际执行三项导出CLI拒绝检查：错误program identity、错误内容SHA、重复时间样本均exit1且未生成trace，证据 `validation/campaign/trace_comparison/model_export_negative_cli.json`。

比较器当前18项独立测试通过，含嵌套RNG/state字段的bool/int与int/float区分。模型导出及比较输出均保持实际游戏准确性false，不能作为客户端黄金轨迹。
参数、标准格式和已执行命令见 [轨迹工具使用说明](TRACE_COMPARISON_USAGE.md)。
