# 第八章中途数值审计

新生产底座 82db 的全套测试与回放验证已经通过；中途数值仍需要独立来源预期。
本批审计读取 JT8-2 V7 和 JT8-3 V4 在 700 帧时实际保存的检查点事件前缀。
读取时重新核对事件数和整个封存前缀 SHA，既不读取正在增长的尾部，也不修改运行输入。

独立算术位于 `tools/trace_audit/chapter08_arithmetic_v1.py`，不调用被审计的运行提供器来计算预期。
`chapter08_stream_v1.py` 先将规则、参数、提供器源身份及规则运行时身份与当前内容绑定，
再比较独立结果、trace.raw、trace.value 和公开计算事件的值。
数值类型和结构也参与比较，没有以排序或近似值掩盖差异。

本批覆盖如下明确子集：

- 灼烧名义时长消耗倍率：抵抗倍率上下限与倒数。
- 灼烧伤害：父 Buff 有效性、唯一子 Buff、子起始时间、30 秒线性递增与封顶。
- 火山触发间隔：来源最小／最大间隔与实际单个随机样本的换算。
- 塔露拉和黑蛇部分技能：ASPD 对前摇、持续时间及量化后冷却余额的影响。
- 黑蛇视觉开关：模式 2／3 的来源条件。

JT8-2 前缀独立重算 223 次，JT8-3 前缀独立重算 5814 次，全部相同。
收据是 `validation/trace_audit/chapter08_native_prefix_v2/verification.json`，SHA
`9bb998a715d9dd00ae064a6b0ce6b228b6319d0d519c4d3cda70ac0279722a71`。
报告列出所有尚未覆盖的计算次数，`all_intermediate_fields_verified` 保持 false。
它不证明每个伤害结果、每个移动坐标、完整随机算法或整关已经正确。

13 项额外作者检查使用不同倍率、伤害参数、时钟和随机样本，并确认实际输入、参数、
提供器摘要、规则摘要、运行时摘要或 raw 类型被篡改而输出不变时仍拒绝。
新工具自身还在独立复核，不能把作者结果直接认作独立通过。

后续独立复核用真实小轨迹发现三处身份拒绝缺口：contract_version、calculation_id 和
逻辑 time 的 bool 值被篡改时，旧工具仍接受原输出。这些反例保留。
新的 V2 算术与流审计器加入契约、时间类型、实际量子、秒数、输入时钟、公开事件与演员身份绑定。
动态 Buff 寿命使用明确的前一区间采样政策，允许真实 sampleT 在 T+1发布，
拒绝 T+2 及普通计算借用此例外。32 项修订作者门与 Root另8个不同量子/演员的独立门通过。
已经删除的700帧大前缀没有在新版工具中重新审计；旧6037次结果保留旧工具身份，
不能把修复后的工具测试迁移为新版本已核对完整前缀。

第一个入口误读了检查点中不存在的单独规则运行时字段，实际在算术审计开始前退出失败。
原入口及失败收据保留，V2 入口使用公开组合运行时指纹及实际规则运行时身份，另存新报告。
客户端没有执行数值捕获；用户按约定在完整仿真后统一核对反馈。
