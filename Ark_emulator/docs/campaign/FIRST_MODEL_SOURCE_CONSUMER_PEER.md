## External sidecar design review

An external contract can preserve battle bytes and bind content, commands, contract, core, native source and roster separately. This avoids changing executable identity solely to store review metadata. It cannot repair omitted executable scheduling by describing the omission differently. M14 changes executable semantics and therefore requires its own complete witnesses.

The current gate source `tools/campaign_model_acceptance.py` SHA at review was `afa3d0c0bc54f277eba544c9a4aab996ad1d67e5c4fe4c15c6931c39306d73b6`. Its existing external-contract suite passed 45 tests in 1.98 seconds. These tests are author tests and are not the independent counterexample below.

A concrete source-review boundary gap remains: `review_gate` feeds each source-review reference to `checked_artifact`, which only checks file SHA, `passed`, and any supplied test source rows. It does not require a source-review schema, subject content/native/core binding, or semantic category coverage. The independent probe `validation/campaign/external_gate_peer_source_scope.json` actually passed an unrelated schema, wrong content/core and different native level through that boundary. This is a boundary-level counterexample, not a claim that all other full receipt gates were bypassed.

Raw-value, semantic-consumer and executed-mechanism checks should each state their coverage; five unbound receipt strings cannot substitute for those scopes.
