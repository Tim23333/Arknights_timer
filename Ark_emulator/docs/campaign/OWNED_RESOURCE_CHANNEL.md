# 有限持续通道的资源包

第十章10-17工匠充能需要通用持续通道修改资源。实际反例位于
`validation/campaign/chapter10_stage17_ordinary_v1/dmech.channel.counter.v1.json`：
已拥有能力经 `wait_for_channels` 与 `begin_attachment` 引用有限20秒通道，
当前冻结9a核心明确拒绝 `modify_resource`，因此尚未建立模拟。
这个缺口不能由0伤害包、一次性增加SP或Manfred充能接口代替。

下一底层扩展沿用通用 `AttachmentSystem`，允许显式的 `modify_resource` 包。
资料中的目标、SP键、正负增量、时钟、20秒持续时间和中断行为由内容定义；
内核不识别敌人ID、城防炮或关卡号。保留拥有者、真实能力／cast、目标、生命周期、
任务ID／次序／到期时间、有效Buff、公开终止原因和最大包数等校验。
非伤害资源包必须显式关闭 `damage_integral` 并声明命中间隔，
资源键和数值字段通过现有效果／资源契约校验，不允许把伤害积分当作SP积分。
资源不存在应报错；正向恢复冻结、容量限制和负向扣除保持实际资源规则。

新增机制需单独候选，在元素恢复冻结之后从确切父版本派生；不修改活跃运行的源码。
实际验收至少包括：

- 有限包时钟、容量截断、非默认资源名和两种独立数值配置。
- 目标／来源死亡、撤退、隐藏、控制中断和终局取消后不再修改资源。
- 公开中断、真实任务和cast一致；直接调用、陈旧代际和伪造任务不能授予包权限。
- 资源修改或回调发生异常时world、调度、RNG、事件与缓存恢复到真实事务边界。
- 完整磁盘CP续跑、公开head、全部状态和事件一致，保留父核心拒绝反例。

工匠消费者另外需要来源驱动的前摇／后摇、单次技能触发、5SP、CD5、
每秒1充能、20秒连接、静默／控制中断及真实炮选择器上的-15SP回调。
这些内容门不由底层资源包通过自动满足。现有材料没有找到“.9阈值”的原始数值，
若采用参考规则必须注明可替换来源，不能声称已从原字段恢复。
本文为后续开发要求，不代表底层或工匠完整机制已经通过。

2026-10-07 通用资源包08b6的9组开发门、9组独立门、完整1219／0-1／自定义公式基线均通过，

工匠来源进一步核对发现两个实际边界。原 `AbilityStandard.Event` 的4为ON_SPELL_ON，
3为ON_CAST_END、6为ON_ATTACK_FINISH，因此原BuffToOwner必须在前摇之后的真实施法点挂载，
不能在cast开始时直接当同一事件。首次内容草案保持历史身份，不批准原生完整行为。
新的 `pure_silence.counter.v1.json` 实际公开tick220施加flag12：控制投影仍允许能力／攻击／移动，
没有触发stun式中断；连接因source_flags真实停止、已发生2包、炮SP33，
但tick260原charge仍活跃且finish_at793，原结束扣15SP尚未执行。

需要08之后另一个候选增加显式选择的通用通道阶段策略：按实际拥有通道结束计算后摇、
真实任务／cast／原结束原因认证，取消原名义finish任务或正确转移其权属；
其时长须经可替换数值／时间规则量化。旧技能默认行为保持原语义，
非声明通道、伪cast、直接调用、重复／陈旧释放不能授予提前结束权限。
静默、stun／freeze、自然结束、来源／目标退场及终局各走真实路径，
同时检查回调时点、资源扣除、Buff释放、完整CP/head和异常五存储回滚。
不得用强制stun中断或即时扣SP代替来源中的纯沉默路径。
