# 第九章运行底座需求

目标仍为冻结主线目录中的两关：9-18（main_09-16，34 次出生）与
9-19（main_09-17，63 次出生）。两关的数据收集使用固定表版本及分别封存的资源来源。
原生地图、分支、预放置、卡片、部署费用、槽位与控制都需要消费，
仅基地生命值覆盖为 99999。源准备目录不表示已经创建运行模型。

本章首先需要把以下通用能力补齐或组合，之后才生成完整关卡包：

| 能力 | 运行契约 | 需要来源确认的参数和顺序 |
|---|---|---|
| 元素累积与爆发 | 每种元素有独立累积资源、阈值、恢复和爆发状态；伤害请求独立表达普通伤害与元素积累；触发、锁定、结束和清空顺序可替换 | 原生 DamageInfo 的元素类型、比例、阈值、耐受恢复、爆发时长与效果，不根据名称硬填数值 |
| 可摧毁石柱 | 保持柱体 HP、可被攻击标志与倒塌状态；公开方向输入产生显式路径及沿途碰撞效果；结束产生有限碎石地块或阻挡实体 | 可受攻击与死亡 Buff 的原层级、倒塌范围、伤害、控制、目标类别、地形转换和移除顺序 |
| 重复预放置标记 | 保留来源中的重复 alias，转换层提供按来源记录序号绑定的唯一运行身份；技能按明确选择规则取得对象 | 9-18 原生三个柱体的重复标记如何被不同能力引用，不静默合并、删掉或重命名来源字段 |
| 多阶段敌人 | 状态图控制地面／飞行、石化保护、恢复、复生等待、当前技能和攻击资格；在途弹道保持原来源 | 石像鬼与曼德拉的模式、黑板前缀、阶段进入／结束回调及动画生效事件 |
| 光环与双重资格 | 组合已有属性层、可沉默 Buff、相对阵营选择、光环成员与源所有权；多 checker 逐项执行 | 折射法抗、护阵者防御、影刃目标、护盾减速及沉默时实际变化 |
| Beam 与按当前生命取值 | 通用周期命中支持不同时间的源／目标快照，伤害规则可读取当前 HP；射线与柱体交互不按 Boss ID 分支 | 命中间隔、持续时间、当前 HP/属性采样时点、Ray 范围、阻挡与终止条件 |

元素系统的数值计算应是纯规则；请求接受、资源变化、爆发状态和结束属于领域写入。
内容可替换积累量、阈值、恢复率、锁定条件和爆发效果，但不能绕过原子性或回放身份。
已有 Resource、Buff、Effect 与事件订阅可以承担部分组合；
需要新增领域原语时，以真实来源反例证明组合不足，再在隔离候选中开发。
任何新原语都应具有非法输入拒绝、回调失败回滚、同时触发顺序、源退场和检查点／重放验证。

敌人数据中的曼德拉原黑板与技能黑板存在同名短键的不同前缀。
复生等待、无敌和召柱冷却必须按组件路径分别解析，不能用整段列表互相覆盖。
固定元素爆发表中 FIRE 的十秒配置已出现，但阈值、爆发伤害及恢复数据尚需完整来源闭包，
在确认前不把通用字段解释为已实现的实际游戏机制。

开发批次优先完成普通敌人的基础战斗、折射与光环消费者，
同时在独立场景完成元素和柱体交互，然后再联结石像鬼与曼德拉阶段。
每批都使用当前独立 V2，冻结来源、内容、算法和运行身份；
第八章正在执行的输入与旧通过证据保持其原身份。
