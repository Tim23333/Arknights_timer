# AdvancedSelector source audit and M25 eligibility proposal

No core is changed by this document. Actual audit tool `tools/experiments/selector_source/audit.py` reads five W/mocock Advanced/Secondary selectors from original CAB typetrees, hashes assets, and extracts exact declaration text from dump.cs. Output `validation/campaign/advanced_selector_source_audit.json` locks enum/source identities.

AbnormalFlag is an enum index:TARGET_FREE2, HEAL_FREE7, CAMOUFLAGE17, SKILL_NOT_ACTIVATABLE24, TELEPORTED44, E_NUM46. AbnormalCombo is SLEEPING0/SHELTERING1/E_NUM2. These are not the serialized selector's bitmasks. Attribute manager separately stores long abnormalFlagMask and counters; its conversion/getter methods are stubs. Current selectors have ignoreTargetFree0, onlyIgnoreSome0, excludeSomeAbnormalFlags0, needProfessionMask0. Inspect attributes show flag/combo nested under onlyIgnoreSome, and excluded flag under exclude-enabled. Therefore W24/mocock44/excluded46 are inactive configuration, not filtering conditions. Opposite or invalid inactive values must not affect eligibility; enabled unknown/invalid real flag values must fail compile.

SideTypeIndex is absoluteALLY0/ENEMY1/NEUTRAL2; SideType is masksALLY1/ENEMY2/BOTH3/NEUTRAL4/ALL7. The current selector enemy2 is interpreted by an explicit relative-to-source ally/enemy model: W enemy source selects ally players; NPC ally selects enemies. This is a declared model, not a recovered ValidateTarget body. Neutral-relative handling should be explicit or rejected when ambiguous. MotionMask WALK1/FLY2/ALL3, EntityCategory DEFAULT1/TRAP_OR_ITEM2/OBSTACLE4, UnitTypeMask CHARACTER1/ENEMY2/TOKEN4, and ProfessionCategory powers1..512 with CHARACTER639/ALL1023 have distinct typed masks. They must not share AbnormalFlag encoding.

Actual recorded Buff attributes.abnormalFlags arrays include tokenHEAL_FREE7, EMPINVINCIBLE5 and stunSTUNNED0. They provide concrete status-writing representation. Current sampled source closures contain no explicit target-free or camouflage writer. Entity.get_isTargetFree/isTargetFreeWithImmuneFlag/isCamouflage and owner.canSelectCamouflageTarget exist, but dump bodies are empty. We must not derive target-free automatically from stunned/skill-not-activatable or assume the inactive44 field means a teleport prohibition.

## Minimal generic interface

Use selector.eligibility={rule:exactID,parameters:{source_configuration:all raw selector fields,side_policy:relative_ally_enemy,neutral_policy:explicit...}}. Add pure per-candidate `targeting.eligibility` contract with source snapshot, candidate snapshot, selector configuration and structured selection states; return boolean or decision accepted/reason. The rule performs eligibility only. It does not calculate range, order, score, sample RNG, emit or modify state.

Actor `components.selection_state` explicitly stores absolute side index, motion/category/profession/unit-type values, base abnormal flag/combo sets, target_free and its typed reason sets, ally_target_free, heal_free and camouflage capability. Buff `selection_flags` contributes explicitly declared status/reason sets during its live half-open interval. The projection is readonly, checks expiry against current time, and never calls prune/controls or a mutating attribute getter. Stack contribution union/removal keeps independent causes; status source fields stay provenance-bound. No arbitrary official actor IDs enter the core.

Target-free must be respected because ignoreTargetFree is false in current sources. The supplied model rejects target_free active, while ordinary alive/active and route visibility remain independent mandatory prerequisites. Camouflage rejects unless the source explicitly can select camouflage or the selector's forceIgnoreCamouflage is true. Profession/unit type gates run only when their enable booleans are true. Category/motion and source-relative side are real consumers of current fields.

An optional enabled partial target-free ignore is a replaceable reason-set model: ignore only the selected known flag/combo cause, rejecting any remaining cause. E_NUM is not a live flag. This aggregate algorithm is explicitly mathematical because native IsStillTargetFreeWithImmuneFlag is not recovered. For the current false flags no such optional aggregate is needed, and inactive values are not read at runtime.

SpatialSystem.eligible(source,selector,ability/effect,primary) should be shared with M24's pure geometry/candidate query. M24 handles existing provider/filter/region without sorting or RNG; the per-candidate targeting.eligibility stage plugs into that same flow. select() and FSM has-target must share it, preventing one from accepting an actor the other cannot attack. No-config path preserves old behavior/events. Custom eligibility rules remain replaceable and kind/contract checked; unsafe missing state cannot become implicit native certainty.

## Independent expected tests before integration

Current W/mocock selectors:target-free excludes; two ordinary targets with different24/44 states behave identically while partial/exclusion gates are disabled. Camouflage rejects/force-ignore or declared source capability permits. False switches with contradictory/unknown inactive numbers do not leak; enabled unknown enum rejects. Exact side/motion/category/profession/unit masks and foreign rule kinds reject. Independent Buff causes preserve status until last owner/removal and exact expiry; pure query leaves complete checkpoint/RNG/events unchanged and has no hidden sorting draws. Actual select/cast and M24 has-target agree, including dormant/route hidden and source/target retirement. Public Buff/skill commands drive status changes and complete CP/replay fixtures.

Native side/filter aggregate priority/target-free reason conversion/getter, camouflage discovery, postFilter sorting and attack/move FSM bodies remain client pending. This proposal consumes explicit status/profile mathematics rather than leaving current enabled target-free requirement as a vague unimplemented gap. Separate M25 candidate should copy frozen M23 0258, not change c069/M24/old inputs; Root will merge after design confirmation.
