# M42 synchronous aura membership removal

This isolated candidate extends M38 `2165e5e267fa62012867d7676e0ad68f53234217e0b62fec31ace3956f23fdd6`. Only `ark_sim/domains/buffs.py` changes. Frozen candidate: `../unpack_work/campaign_m42_aura_remove_candidate`, implementation digest `2746020dd269241d8802551ea63cb28243755ff0105a19bb09033c448f497420`.

Removing a source qualification Buff formerly left its aura membership unchanged until the next maintenance tick. The preserved M38 counterexample in `validation/campaign/defdrn_status/remove_history_m38/counterexample.json` shows an immediate attack receiving 900 damage when removing silence should restore DEF300 and yield 600. This is a same-frame consumer mismatch, independent of unknown native callback details.

The public remove operation now encloses removal, recursive child cleanup, on-remove effects and the final membership reconciliation in one transaction. A removal-depth guard postpones reconciliation until the outermost successful removal finishes. The existing reconciliation guard prevents reentry; both guards restore in `finally`. Failed effects/providers roll back resources, Buff instances, aura membership, jobs, events and RNG. A missing Buff removal does not create new events.

`tools/experiments/m42_aura_remove/verify.py` ran six independent generic cases and eleven source-backed defdrn cases: **17 passed**. The cases cover manual removal, half-open expiry, same-frame attack settlement, parent-child cleanup without reapplication, source retirement, repeated failing reconciliation with full rollback, plus recorded-command checkpoint and replay.
