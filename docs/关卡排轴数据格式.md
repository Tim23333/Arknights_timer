# 关卡地图与排轴 JSON

桌面端完成“敌人数据”扫描后，可点击“导出关卡/出怪”生成
`arknights-stage-strategy` v1 文件。该文件可直接导入前端，并可再次导出为完整排轴。

## 敌人出场种类

- `scheduled`：固定波次。来自 `LevelData.waves/fragments/actions` 的 SPAWN。
- `conditional`：条件分支、隐藏组或随机出怪组。触发前可能没有可靠绝对帧，前端放在“待触发区”，不会伪造时间。
- `summoned`：关卡敌人数据库中存在、但不在固定波次或分支中的类型。通常由召唤技能、死亡转阶段或关卡事件生成；触发前数量可能未知。
- `dynamic`：扫描期间才在运行时发现、静态计划中不存在的实例。

随机组另外保留 `randomSpawnGroup`、`randomSpawnPack`、`randomType` 和 `weight`，便于区分同一分组里的候选项。

## 顶层结构

```json
{
  "schema": "arknights-stage-strategy",
  "schemaVersion": 1,
  "timeline": { "fps": 60 },
  "stage": { "stageId": "", "levelId": "", "code": "", "name": "", "mapId": "" },
  "map": { "rows": 8, "cols": 12, "tiles": [], "blockEdges": [], "devices": [] },
  "routes": [],
  "enemySpawns": [],
  "operatorActions": []
}
```

地图格子保留原始 `tileKey`，同时给出稳定的 `category`：敌方出生点、我方蓝门、传送入口/出口、地穴、不可用、高台/墙、障碍、装置/机制和普通地面。无法归入基础地形的新 `tileKey` 会作为装置/机制展示，不会丢弃。

每个 `enemySpawns` 项表示一个敌人实例。`startFrame` 是时间轴出生位置；`endFrame` 是扫描到的死亡/离场帧或攻略作者手动填写的转阶段帧。结束尚未知时必须为 `null`，前端以右侧虚线表示。

## 我方操作兼容导出

前端“仅导出我方操作”继续使用桌面端现有格式：

```json
{
  "settings": { "map_code": "1-7", "map_name": "暴君" },
  "actions": [
    { "action_type": "部署", "frame": 120, "oper": "能天使", "pos": "F9", "direction": "右" },
    { "action_type": "技能", "frame": 600, "oper": "能天使", "pos": "" },
    { "action_type": "撤退", "frame": 900, "oper": "能天使", "pos": "F9" }
  ]
}
```

部署、技能、撤退在编辑界面中是三个独立大类；每类可以添加多个干员行，同一行也可以有多个动作点。
