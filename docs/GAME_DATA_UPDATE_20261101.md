## 已修复的适配缺口

1. 当前 `StageData` 在 `stageDropInfo` 后新增 `levelMapId`。旧固定字段表会使
   后续标志、字符串、向量错位，并导致关卡解析异常耗时。现在由当前结构源生成
   `schemas/table_fields.json`，解析器按版本字段顺序读取，兼容旧 bundle。
2. `AttributesData` 新增 `blockVolume`。角色属性解析使用同一版本 schema，
   保持后续浮点属性的含义；支持阻挡体积、阻挡半径比例及免疫布尔值。
3. 关卡布尔值按单字节读取，避免把相邻标志拼成大整数。
4. `BattleCharacterData` 的技能、天赋、装备等字段由更新器生成，不再全部继承
   旧布局。关键字段缺失会中止更新。
5. 战局生命周期检查和暂停状态读取使用 Android profile 的偏移；保留身份、
   反向归属、重复读和换局检查。
6. Scheduler 协程数字后缀改为版本数据。生成阶段要求每个方法只有一个候选，
   并验证读取器依赖的全部迭代器字段。Android live 字段表确认主链为
   `119/123/124`，DefaultWaveHandler 内部协程为 `24/25/26`。
7. 打包入口将 `schemas/` 纳入运行时数据及其 manifest。
8. 实测确认 DefaultWaveHandler 的 Scheduler 引用由 `0x18` 移到 `0x28`，
   已加入 profile 映射。前后延迟协程捕获的是当前 WaveData，按实际对象归属
   和阶段检查；行动队列协程仍验证 Handler 归属。保留活动链、尾部重复读和
   同帧守卫，未添加客户端版本号白名单。
