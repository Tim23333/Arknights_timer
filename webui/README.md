# Timeline Web UI

本目录是主程序的实时 Web UI。`frontend/` 保留独立排轴工具；设计参考已审定的离线原型，但原型不属于发布资源，也不要求随仓库提交。此界面使用原型的左侧抽屉、游戏时钟置顶抽屉、完整模块总览、单行六入口和气泡提示，全部数值来自后端，没有模拟值。

从源码使用主程序的 `--webui` 参数启动，打开主程序输出的本机地址；`--webui-port` 可指定 HTTP 端口。界面只在启动时通过同源 HTTP 读取完整展示快照，随后通过两个独立 SSE 通道接收时钟和模块变化，通过 HTTP 命令桥由 Qt 主线程执行扫描等操作。WS 服务关闭或字段 WS 发布关闭，不影响本地展示。

字段策略读取后端注册表，逐项提交带策略代际的改动；依赖冲突由后端拒绝，前端刷新真实配置，不自动打开其他采集项。表格在刷新时复用行和控件，只在列定义发生变化时重建表头；设置、抽屉、搜索、展开状态不随高频采样重置。浏览器按 requestAnimationFrame 合并同一主题的最新快照，后台页面暂停绘制时也不保存逐帧队列。

设置页不直接展示策略代际数字；并发校验和缓存隔离仍保留代际属性。总览及设置页不再常驻自动检测进度横幅，过程反馈使用已有气泡和日志，完整状态仍可在运行设置的“全部运行状态”中查看；自动检测开关与后端行为不变。

`/api/stream/clock` 直接跟随已成功提交的计时器采样，不等待 Qt 的 100ms 状态定时器，不增加内存读取。秒数显示到两位小数，逻辑帧和来源帧保持真实采样；不估算、不插值，也不保证上游读取器能逐帧采全。敌我帧不会改写时钟的来源帧。`/api/stream/modules` 在新批次到达时唤醒 Qt，合并待处理通知，只发送变化的主题；低频服务状态仍由 100ms 定时器维护，不重投影未变的实体表。时钟更新不触发表格或完整 JSON 重绘。

每个 SSE 通道最多四个连接，保留普通 HTTP 工作槽用于命令。后端每主题只保存一个最新序列化快照，慢客户端跳过被替代的数据；浏览器也每主题只保留一个待绘制值。已有套接字缓冲及浏览器解析/绘制仍可能形成延迟，这不等于所有字段达到 60Hz。断线显示最后已知状态并自动重连，重连发送当前快照，不重放历史。后端重启及换局会显式清空缺失的来源主题。SSE 仅绑定本机并验证同源，不受对外 WS 端口、启停或发布频率控制；采集与本地展示策略仍有效。

实体详情显示完整基础对象、字段状态及异步详情，并明确保留来源元数据。总览每个模块可以展开所有列/事件和完整 JSON；随机数两条引擎均显示真实字段、全部返回预测和消耗记录。未知值显示 `—`，不补造 0。时间来自计时器链，与敌我来源帧各自标记。

实时数据表格使用固定布局和按字段键保存的列宽，敌人/干员默认宽度直接使用桌面端列定义。数据更新、空值、行的增减与分页不会自动撑大或缩小列；数字使用等宽数字排印。点击“列宽自适应”只按当前页文字测量一次并固定结果；双击列标题右侧边界，仅自适应该列，边界控件获得键盘焦点后也可按 Enter 或空格触发。隐藏再显示某列仍保留本页会话的已调整宽度，刷新网页则恢复默认。自动测量单列上限为 480px；表格不足容器宽时不再按比例拉伸各列，避免调整一列影响相邻列。超长文本仅在表格视觉上省略，悬停可看完整文本；详情、完整 JSON、导出与 WS 原值不截断。普通采样刷新不执行文字测量或重新写入列宽。

“关卡与操作”使用中文表头及操作、朝向和逻辑帧匹配来源名称，保留操作记录全部返回字段。关卡摘要只显示关卡编号、名称和标识，不直接把 `stage / squad / meta` 协议对象当成卡片；编队仍用于补充干员名称。折叠的完整 JSON、导出、后端与 WS 保留原字段和枚举，不受中文显示影响。同一干员的部署、撤退和技能各占独立记录行，不按干员唯一标识合并。

“干员监控”提供“采集全局总伤”和“无来源总伤”快捷开关，分别修改已有字段策略 `character.global_total_damage.collect` 和 `character.unattributed_damage.collect`，并非仅隐藏列。无来源统计依赖有效的敌人 HP 和干员累计输出；读取失败时不会伪造统计。依赖冲突仍由后端拒绝，展示和 WS 发布开关继续独立控制。

“全局总伤饼图”弹窗展示干员输出及治疗占比饼图与分页明细，复用原桌面端按干员标识取最大累计值的合并规则，不把重复实例相加；包括已撤退干员的最后已知累计，排除召唤物/装置和全局汇总伪实体。缺少读取成功证据的值不计入饼图；未采集、未展示、源停止或策略代际不匹配时不会用旧缓存恢复有效值。HTTP 断开明确标记为最后已知累计。此本地展示投影不依赖 WS 开启，也不改变 WS 协议。干员表格的“全局总伤”按自身字段状态显示数值，不依赖“无来源总伤”开启；该列是整场共享总量，不应将各干员行重复相加。

敌人血量、干员生命与技力均展示当前值/最大值，支持零值及小数设置；它们不会再依赖桌面端专用进度条才能显示。敌人“编号”读取游戏已加载的 `EnemyHandBookDB → enemyData → enemyIndex` 内存链，不使用本地敌人数据表补值；首次定位在扫描阶段，已验证的静态数据按游戏进程维护，并在重扫时校验 DB 引用和字典版本。关闭编号采集后不解析或合成该列；此前从未定位图鉴的情况下重新开启，需要点“重新扫描”定位，未就绪时明确显示不可用。

敌人已离场但从未被实时采样时，保留从关卡计划获知的名称、敌人 ID、生存状态及内存图鉴编号；只有未经采样的实时属性显示“不可用”。已成功采样的历史实时属性继续保留其原来源帧，绝不改标为最新实时值。“离场敌方不显示”依据保留的生命周期正常过滤这些行。

已离场区域保留 `endReason` 分类，并优先按原始 `finishReason` 显示中文原因；新增“原始原因编号”列和各类型筛选。原始值来自现有 Entity 内存块，未读到返回 null，不从 `death`、`reach_exit`、`finish_N` 或血量反推。0=未结束、1=到达出口、2=生命归零、3=坠落、4=撤退/撤出、5=死亡式撤出、6=静默撤出、7=其他原因、8=无伤害来源的生命归零、9=被替换、10=自身重生、11=自身移动式重生、12=外部移动式重生；未知编号直接保留。阵亡筛选包含已观测 DEAD 分类或原始 2/8，不把坠落、撤出和重生一律判为击杀。`enemy.finish_reason` 接入运行设置中的采集/展示/WS 发布开关；关闭采集后清除原始原因缓存，再开启不会补回已离场对象的编号。终止原因的来源帧与最后存活 HP/位置分开，后端和 WS 数据仍保留二者区别。

终止状态可能比原始 finish 标志先变化：若 `endReason=death/reach_exit` 而 `finishReason=0`，原因栏仍显示已确认的阵亡/到达出口分类，原始编号列保持真实 0，不把 0 改写成 2/1。

选择 ADB 支持手动路径、异步本机文件选择、探测运行中的模拟器及其自带 ADB、刷新设备地址、在线设备选择和读取当前配置。设备列表明确区分在线、离线及未授权；保留手动填写地址，与桌面端共用 `memcore` 的探测、版本验证和连接逻辑。文件浏览打开运行 Timeline 的本机窗口，不上传文件。探测、刷新和浏览不应用配置；点击“使用此 ADB”后重新验证程序及在线设备，只有一个在线设备时允许自动补全空地址，多个在线设备必须明确选择。

顶部“自动寻址”按钮触发一次 guest 侧游戏时钟寻址；成功后沿用现有时钟读取链，失败由气泡提示。它不改变运行设置里的持续“自动寻址”开关，也不会自动重复扫描；如果已有定位任务在执行，后端拒绝重复启动。旁边的“寻址工具”仍打开原有手动寻址程序。

慢 ADB 操作使用可查询/可取消的异步任务，不阻塞 Qt 时钟和 HTTP 状态刷新。切换自动请求旧敌我、部署、随机数监控停止，等停止完成才替换读取器并保存配置；扫描定位期间拒绝切换，验证期间来源改变也拒绝旧结果。关闭 ADB 抽屉会请求取消尚未完成的任务；已发出的停止请求不会自动恢复监控，已完成的切换也不回滚。配置保存失败会独立警告，不伪装为持久化成功。单个 worker 的已有 ADB 子进程受原有超时约束，取消后迟到结果不会再应用，也不会启动无限个 worker。

WS 可达性自检真实连接后端提供的 v2 游戏端点，按已同意发布的注册字段订阅，逐项检查有效值。零值、false、有效空数组通过；null、缺字段、无场上对象、未采集和读取不可用分别报告。心跳或仅收到主题不算字段验证成功。自检不验证未来每帧的稳定性。

实体详情抽屉在替换为教程、日志或其他抽屉内容，以及关闭时都会释放后端详情目标。选中与取消命令串行执行，快速切换跳过已经过时的选择；旧取消完成后才设置新目标。请求失败通过气泡提示，不能根据 HTTP 失败断言后端从未应用该命令，因此后续切换仍尝试释放可能已应用的目标。

正式 EXE 只打包本目录根层的生产 HTML/CSS/MJS 资源，不递归包含 `test/` 或 README；浏览器回归页和 Node 测试继续保留在源码仓库。三个布局/刷新回归页使用同源外部模块与 `test/regression.css`，兼容生产服务的严格 CSP，不需要放宽内联执行权限。

文档以安全文本节点渲染标题、段落、列表和代码块，原始 HTML 不执行。HTTP 服务仅绑定 127.0.0.1，限制请求大小、并发和来源；后端工作线程不直接操作 Qt 或游戏内存。

验证：在仓库根目录执行 `node --test webui/test/*.test.mjs` 与 `python -m unittest backend.test_webui_server`。无需 npm 安装或构建，无第三方运行库和 CDN 请求。

列宽的浏览器回归页位于 `test/tableLayout.html`，只使用明确标识的合成数据，不连接游戏。可在本目录运行 `python -m http.server 8770 --bind 127.0.0.1` 后打开 `/test/tableLayout.html`；测试按钮连续切换短值、长值、空行和重新出现的行，报告列宽偏差，手动自适应后可再次运行。

相同可见数据重复刷新不会写入表格或分页 DOM。表格按稳定行标识、当前页列定义及实际展示文字判断更新；仅最近已知帧等未显示元数据改变时不重画历史表。值、行顺序、筛选、页码或展示列改变时仍正常增量更新，不暂停采集或后端轮询。`test/refresh.html` 使用真实 DOM 与 MutationObserver 检查 30 轮无变化刷新、行/按钮复用、真实值变化、行排序、空表恢复及翻页。

敌人和干员主表由 `fieldDisplay.mjs` 处理短暂读取失败的展示跳变：新有效值立即显示；失败时最多保留最后一次有效读数到其收到后的 500ms，文字旁标“旧”，悬停显示“非当前值”、原来源帧和失败原因。连续失败不会延长期限，过期即显示“不可用”；没有读到过的属性不补值。换局、ADB 切换、源停止、策略代际或小数格式改变会清空保留值，关闭采集或展示也不会恢复旧值。单次过期定时器不增加采集、推送或游戏时钟频率，不进行数值插值。标记预留固定宽度，正常与保留值之间切换不会横向推移文字；刷新时直接更新既有 Text 节点，不将单元格内容删除后重建。

这只是明确标记的网页短暂保留，不修复底层读取失败，也不宣称旧读数是当前帧。详情、原始完整 JSON、导出、WS 协议和字段状态保持本次原始采集结果；已离场历史区仍按后端历史证据展示，不用网页保留值改写历史。刷新回归页还覆盖 30 轮跨绘制帧的有效／失败交替、无子节点重建、标记不推移文字、500ms 过期及有效值即时恢复。

敌人／干员表头的采样说明采用独立的状态文本、标签和固定 10 位等宽帧号框。帧号从数值变为“—”或位数变化时，框和旁边文字不移动；未知来源帧仍显示未知，不借上次帧号掩盖失败。旧值保留提示放在模块状态栏，不改变表头宽度。`test/sourceMeta.html` 以合成帧号覆盖 30 次数值／未知交替、F0 与 10 位帧号、框位置及文本节点复用。

## 实时日志、展示分页与自动刷新

敌人主表下方的“已离场敌人”默认折叠，按“全部 / 已确认阵亡 / 其他或原因未知”筛选，复用独立分页与固定列宽。只有观测到 DEAD 状态的记录归入已确认阵亡；进入目标点与原因未知不算击杀。后端公开 `endReason`、`endFrame`，分别由 `enemy.end_reason`、`enemy.end_frame` 三层策略控制；字段不要求额外内存读取。离场帧是首次观测离场的帧，并非保证准确的死亡帧。血量与位置保留最后成功采样值及其原来源帧；中途启动而未见过的动态数据仍不可用。“历史快照”仅打开已保存、已投影的完整基础 JSON，不向已回收对象发起异步详情读取。主表隐藏离场记录不隐藏此区域；换局按后端会话数据更新，不在网页另存跨局历史。

操作记录的逻辑帧来自计时器的时间—帧缓存精确匹配或相邻样本插值，不是 BattleLogger 自带字段。开启监控之前发生的操作通常缺少对应缓存，`frame=null` 时显示“不可用（无对应时钟采样）”，不使用 timestamp×固定帧率编造帧号；合法 frame=0 显示 F0。已捕捉的 frame 值正常显示。

左侧“配置与服务 → 实时日志”复用主程序诊断日志。支持站内弹窗及独立浏览器页面（`/logs.html`，旧地址 `/?view=logs` 自动转入）、搜索、暂停显示、跟随最新、清空网页显示、完整 `.log` 导出、诊断 ZIP、刷新环境信息和打开本机日志目录。独立入口使用原生新窗口链接，窗口或标签页形式由浏览器决定；页面不订阅后端实时通道，时钟仅复用同源主工作台的浏览器消息，日志仍使用原有 HTTP 查询。首次打开即读取日志，即使窗口尚在后台；之后后台窗口暂停轮询。后端会话变化时从新游标 0 重新读取，不跳过新会话较早的日志。空日志、搜索无匹配、加载中和读取失败都有提示。测试模式下与原有独立 Qt 日志窗口共用同一日志管理器，不替换或禁用测试版功能。网页缓存最近 10000 行，清空/暂停/搜索仅影响显示；完整日志导出不受这些显示条件限制。ZIP 包括完整会话日志、环境与运行状态、生成偏移文件；存在异常日志时也包含异常日志。导出和环境查询在有界后台线程完成，不在 Qt 线程执行 ADB 环境探测。导出文件直接保存到日志目录；完成后提供可选下载副本链接，不自动向浏览器默认下载目录（可能位于 C 盘）再保存一份。下载位置仍由浏览器设置控制。

独立日志页的时钟由主工作台通过浏览器原生 `BroadcastChannel` 共享，不建立任何 SSE、WS 或游戏内存读取通道。它只显示主工作台已接收的真实快照，不插值或推算；转发在接收阶段完成，不等待主页面的 requestAnimationFrame 绘制，所以主页面在后台时仍可共享。新窗口主动请求当前快照；主工作台关闭、共享更新超过 5 秒未收到或主时钟 SSE 断连时，明确提示等待／最后已知值，不偷偷退回后端读取。浏览器后台冻结可能让共享暂时显示为最后已知，恢复后自动重新接收；每秒的窗口心跳只证明共享页面仍响应，不改变来源帧或游戏时间。多个主工作台打开时接收端保持单一来源，来源关闭或失联后再选择其他页面，防止两个缓存交替显示。主工作台与独立页必须使用同一浏览器且同源（协议、主机、端口一致）；`localhost` 与 `127.0.0.1`、不同浏览器不互通。请从主工作台的“独立窗口”链接打开，或使用独立页的“打开主工作台”入口。没有主工作台时日志查询、搜索、导出仍可独立使用。

日志浏览器回归页为 `test/logs.html`，使用生产组件及真实 DOM、合成的两次会话，验证旧游标返回空页时新会话首行仍能恢复、窗口入口、搜索空态及测试模式。脚本为同源外部模块，兼容生产服务器的 CSP；不会连接游戏或执行日志导出命令。`test/clockRelay.html` 使用真实浏览器消息通道与合成时钟验证迟开窗口的快照获取、零值、刷新来源、断连和停止共享，不建立后端时钟连接；`clockRelay.test.mjs` 另覆盖多个工作台、失联超时和生命周期资源清理。

默认日志目录为程序相对的 `data/logs/`：源码运行时位于仓库根目录下，发布版位于 EXE 同级目录下，不依赖启动时工作目录，也不会写入 PyInstaller 临时解压目录或固定的 C/D 盘位置。可通过显式配置 `TIMELINE_LOG_DIR` 覆盖；安装目录需要可写，无权限时不会偷偷改存其他磁盘。诊断内容可能包含设备地址、本机路径和运行信息；导出仅保存/下载到本机，不上传第三方。日志与诊断包按原有七天保留策略清理，WebUI 增量读取通过会话 ID 和游标区分重启与缓存淘汰。

已观测的计划敌人离场基础历史保存在程序相对的 `data/cache/current_battle.json`，只保留当前一局，不保存逐帧录像或读取器地址缓存。后台线程合并待写任务并原子替换文件，离场历史变化时写入，同局连续性信息最多每 15 秒检查点写入一次。默认目录同上，写入失败记入实时日志，不中断内存采集。

换局失效直接订阅与自动检测关卡变化共用的底层游戏时钟归零事件，在自动扫描开关判断之前执行；关闭自动扫描也会清空旧局缓存，同关卡重新挑战同样失效。重启恢复要求进程出生标识、战斗对象、关卡、帧号和场上实体连续性一致；进程重启、帧号回退或关卡不同不复用，身份暂不可确认则等待、不覆盖潜在同局文件。此前场上实例全部离场时可能无法证明连续性，此时不强行恢复。运行时召唤等无稳定计划身份的历史不跨重启补入，避免与重新分配的序号错误对应。

恢复只合并到当前已离场的同身份计划行，不覆盖场上或未出场实体，不访问旧指针，不恢复本来没读到的属性，也不补异步详情。WebUI、桌面主表、WS 与最终快照导出共用该历史副本，字段保留原 `sourceFrame` / `endFrame` 并标为 `historical`，不会贴上重启后的当前帧。关闭采集会立即从缓存删除对应历史字段，再开启不能复活已删除值；展示与 WS 发布仍分别服从现有策略。

敌人、干员、操作记录、两路随机数的预测/消耗表、字段策略、WS 自检结果和日志提供独立每页条数：5/10/15/20/50/100/全部，以及旁边的自定义输入（1–10000）。翻页只切分展示，不改变采集频率、WS 内容、预测数量或导出。原始完整 JSON 保留全部数据，不做隐式截断；用户可以选择“全部”直接查看完整表格。刷新不重建分页控件或重置当前页；数据减少时只校正越界页码。

自动检测关卡变化沿用桌面端开关和流程：等待时间源 → 等待时钟稳定前进 → 关卡与操作 → 敌人与干员 → 随机数 → 继续监听。设置页和总览不再常驻过程横幅；开始、分阶段扫描、失败重试、等待超时、中止和完成接入后端气泡事件，按原有信息级别、开关与时长显示，完整状态仍可在运行设置的“全部运行状态”中查看。暂停或未开局时继续等待，不把旧帧当成新关卡。页面初次打开不重放过期气泡；日志可用于回看历史反馈。
